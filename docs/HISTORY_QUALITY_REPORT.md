# Balance history and quality report

Delivered: expandable net worth and individual account history, 30/90/365-day/all/custom ranges, step charts, exact date inspection, carry-forward ages and coverage, current-cohort policy, correction-aware entry tables, keyboard access and bounded read-only data access. Saved household balances were not changed by implementation or tests.

The chart does not reconstruct daily prices or historical inclusion settings. Today's included active accounts define net worth history throughout the range; individually archived/excluded accounts remain readable. No account is valued before its first saved as-of date. Missing values stay unknown. Same-day corrections use the latest sequence. Partial lines are dashed and coverage transitions break the line; comparison is unavailable without complete endpoints, and non-positive starts do not get a percentage. One saved date is explicitly described as carry-forward, not a measured trend. Long charts retain sampled extremes/coverage changes while tables and inspection remain exact.

Verification: 25 Node/DOM cases; 10 real-browser cases (desktop/mobile Chromium); 8 rollback database suites. Browser tests use only fake household fixtures and block external requests. The actual production subpath build was also loaded signed out, without clicking a passkey button or accessing household data. Tested screens had no detected automated WCAG 2.2 AA violations, page-width overflow or observed CSP violations. Mock screenshots were inspected. These checks do not constitute comprehensive accessibility certification or native WebAuthn testing.

Fixes found by review: insufficient small-text/footer contrast; date/money wrapping in narrow history tables; a fractional-cent formatting problem for very large amounts; and the previous oversized app bundle. Text contrast, fixed-value cells, exact integer-cent formatting and vendor/lazy chunk splitting address these. Existing category tables, ledger filters, detail dialogs, bulk confirmation, account drafts and sign-out fences remain covered.

Security: read access retains approved membership plus a live server-recorded passkey session. The new helper has no browser grant, fixed search path, strict payload/date/currency scope and resource limits. Notes are returned only in individual history. No stored credentials, real balances, exported records or actual receipt files are used in tests. Advisor notices remain the intentional deny-all private RLS tables, existing disabled-password-provider warning and unused-index information. No new database security warning was added.

Reproduce: npm ci; npm test; npx playwright install --with-deps chromium --only-shell; npm run test:browser; npm run build. SQL fixtures require an administrative connection to the prepared project and must retain their rollback. Browser fixtures are built separately, never deployed, and screenshots/traces are ignored; failure-only CI artifacts expire after seven days. Production output must not contain the tests/browser entry or __householdFixture marker.

Remaining limits: no FX conversion, bank feeds, historical market prices, investment-return calculation or historic inclusion-event reconstruction. Query limits are 500 accounts, 10000 effective entries and 8 MB; narrow the range on a limit error. Safari/Firefox, physical-device WebAuthn and backup/restore remain separate acceptance work.
